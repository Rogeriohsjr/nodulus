# Checkpoint D evidence: OBS-008 and OBS-009

## OBS-008 execution observability

The real built CLI fixture ran two nodes and made five external calls. The first node succeeded; the second returned an invalid response, used two response-only repairs, and ended in `needs_input`; a fresh-process resume then succeeded. Exactly five unique `callId` values were recorded with operations `invoke`, `invoke`, `repair_response`, `repair_response`, `invoke`. The node call counts were one and four. Aggregate input/output/cache-read/reported-cost values were 60/12/0/0. Repeated status reads and a rejected terminal resume did not alter `metrics.json` or the inference log. This behavior already existed after checkpoint C, so the test was characterization GREEN rather than a fabricated RED.

Local Qwen generated the five-call fixture after one rejected draft. The accepted fixture needed one supervisor correction because normal production OpenCode calls use `--agent build`. Qwen test generation exhausted bounded attempts: the 8K primary ended at its output limit and the 12K correction hit the effective 600-second timeout. The supervisor integrated the test. Nodulus clamps provider invocation timeouts to 600 seconds, so the helper's requested 900 seconds was ineffective. This is packet-sizing and configuration evidence; it is not a reason to silently raise the runtime process limit.
