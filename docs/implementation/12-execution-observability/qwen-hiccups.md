## Why 9B became 14B, and what that actually solved

The original installed model was `qwen3.5:9b`. In the earlier experiment it sometimes read/planned without editing, returned empty output or the wrong Nodulus envelope, and produced incorrect source. Increasing context to 32K and adding prose did not yield reliable completion. The coordinator reused already installed `qwen2.5-coder:14b` weights as `qwen-nodulus-coder:latest`, with 16K context, 8192 output cap and temperature 0.2. No model download was needed. The observed GPU was an RTX 5070 Ti with 16 GB VRAM; Ollama reported 14.8B Q4_K_M and about 10.39 GB resident VRAM. This fit the machine and produced usable artifact drafts in checkpoint A.

**Success was bounded:** 14B helped produce inspectable test/helper/correction artifacts and a valid final review. It did not complete either checkpoint unattended. Moving to tool-denied file artifacts, exact source/signatures, JSON-object mode, small assignments and coordinator integration changed at the same time. There was no controlled A/B benchmark, so the evidence cannot attribute improvement solely to parameter count, coding specialization, context size or thinking mode.

For checkpoint B we retried installed 9B as `qwen-nodulus-9b:latest`, context 16384, temperature 0.1, output cap 8192, with the OpenAI-compatible wire option `reasoning_effort: "none"`. [Ollama 0.32.15's adapter](https://github.com/ollama/ollama/blob/v0.32.15/openai/openai.go) maps that option to thinking disabled. Run `66bbf1cb-ca61-4cd2-85cc-31aa497afea4` reached schema success only after two response repairs; the source was still incorrect. Run `f57489b8-ab10-4b67-8d66-47c5320fd395` had no usable final text/reasoning and ended `PROVIDER_RESPONSE_MISSING`. We returned to the 14B alias and OpenCode temperature 0.1. Its small counter function was usable, but larger parsers still required corrections. Recorded reasoning counters of zero are provider observations, not independent verification of internal model behavior.

Both main and auxiliary OpenCode models were local, enabled providers were restricted to Ollama, and the endpoint was `http://127.0.0.1:11434/v1`. Only this task's model aliases were stopped during switches. No GPT builder fallback was introduced. These settings are repository experiment choices, not Nodulus runtime defaults or a universal model recommendation.

## What we can conclude

The workflow retained raw attempts, applied bounded response-only repairs, validated artifacts and stopped on declared failures. The new telemetry measured later Qwen calls without additional inference. The six-node documentation sequence is proven with external-boundary fixtures; the separate artifact documentation node ran live locally.

The complete development flow is **not yet proven autonomous**. The coordinator supplied substantial integration, corrections, test expansion, artifact application and factual review. To claim unattended delivery, a future controlled run must start from a clean allowed worktree, preserve test requirements, perform meaningful RED/GREEN, safely apply changes, update accurate docs, pass fixed checks and independent review, and produce receipts without unrecorded manual edits. The execution report's proposed improvements are not silently marked implemented.
