## Definition

The optional `feedbackRouting` object uses schema version 1 and contains `regionId`, `startNode`, `decisionNode`, `decisionOutput` (`name`, `contract`), `continuationNode`, a non-empty `routes` map, `reentrySafeNodes`, and positive integer limits `maxIterations`, `maxProviderCalls`, and `maxElapsedMs`. IDs must be non-empty safe identifiers. Unknown properties are rejected at every definition level.

The region is the ordered workflow slice from `startNode` through `decisionNode`. The continuation must immediately follow the decision node. Revision targets must be declared nodes in the region. Every node from a revision target through the decision node must appear in `reentrySafeNodes`; those names must be unique and belong to the region. At least one route code must target the continuation. The configured decision output must resolve to exactly one output on the decision node and its declared contract must be loaded and match. The model cannot select a target.

`reentrySafeNodes` is an author declaration. Preflight verifies declarations and node membership; it does not prove arbitrary scripts or external code harmless. An explicitly represented unknown or unsafe/effect field is rejected by strict schemas.

## Runtime routing

Inspection returns the definition unchanged and performs no provider or validator calls and no run-tree writes. Intake captures the validated definition in run context. At execution, the decision node's declared output selects a route code; only codes in `routes` are accepted. A continuation target proceeds in order. A region target replays from that node through the decision node, reuses the completed prefix, supplies the decision and resolved artifact references to the revision node, and removes the old suffix artifacts from the accepted in-memory outputs.

Each accepted region output has a generation ID, SHA-256 of its JSON data, iteration, and attempt result path. A reroute marks prior generations in the invalidated suffix and retains them in `run.json`; the next generations are separate records. The checkpoint also stores the route iteration, replay suffix, reused prefix, pending feedback and provider-call count. Iteration, provider-call and elapsed-time limits stop routing with `FEEDBACK_LIMIT_EXCEEDED`. Unknown decision codes stop with `FEEDBACK_DECISION_INVALID`.
