# P4B implementation split

This is Sol's source-backed preparation while the P4B tests are authored. Neither packet is dispatched until Root observes relevant RED and Root/Sol accept the frozen tests. Keep one writer, bounded source ownership and separate Root verification at each checkpoint.

B1 handles validation and a durable partial answer. Branch to graph handling inside the existing locked resume operation, before the legacy pending/request.json read. Reuse the existing run lock, answer-contract and workspace-reference validation. Share the current graph captured-evidence verifier through a neutral core helper instead of treating diagnostic getRunStatus as authorization. Under the lock, verify schema/engine, exact unanswered runtime ID, pending file hash and node/call/attempt identity, captured definitions/inputs/references/validator hashes, accepted evidence and event sequence before the first write. Unknown, contradictory or partially committed answer metadata fails closed.

Only when other unanswered requests remain, commit the exact bare answer bytes, request.answered event and answerRef/answerSha256 on the existing entry through the single graph writer, with checkpoint last. Return remaining requests in declaration order without any provider method. A safe intermediate B1 rejects a final answer explicitly before mutation until B2 can continue it. Root dispatched these four files after observed RED: resume-workflow.ts, graph-state.ts, new core graph-resume-evidence.ts, and execute-graph-workflow.ts only for extracting the shared captured verifier. Schema2 getRunStatus projection belongs to later public inspection work; it is not part of B1 and is never a resume validator.

B2 handles final-answer continuation. Restore verified accepted artifacts, pending/answered identities, event text/sequence and metrics before scheduling or recording a new metric. The current fresh graph scheduler starts with an empty accepted set, and the writer starts with an empty metrics array; neither is a valid resume default. After all prechecks, commit the final answer, then invoke only eligible answered pending nodes with new call IDs, next attempts and parent IDs from their own completed question calls. Pass each node's validated flat answer merge to both buildPrompt and ProviderInvocation.answers, retaining all historical request/answer/call evidence and immutable inputs.json. Never replay accepted or possibly active work.

B2 source seams include execute-graph-workflow.ts, graph-node-runner.ts, graph-state.ts and resume integration. Update the pending projection guard to compare immutable base fields while preserving verified answerRef/answerSha256; its current exact five-field check rejects answered entries. Preserve declaration-ordered aliases and all previous metrics/events. Fresh-process recovery, crashes, lock/corruption/version/reference cases and caller inputs require their own later tests; they are not accepted by the happy two-node continuation alone.
