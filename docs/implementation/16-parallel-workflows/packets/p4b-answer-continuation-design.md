Planning only; P3 hosted acceptance and P4A acceptance precede dispatch. Source-backed Luna audit confirmed the public signature resumeWorkflow({projectRoot,runId,requestId,answers}, provider, {storage?}); validation failures reject with NodulusError.code. Current schema2 pauses save pending/<uuid>.json, while legacy resume reads pending/request.json before rejecting graph versions. That is an actual public resume gap, not permission to fabricate pending state.

Use an actual seed -> A/B run with distinct answer contracts and real child-process questions. Capture seed accepted refs/hashes and bytes, both runtime question IDs, attempt1/call identities, initial events/metrics and immutable inputs.json. Provider IDs are untrusted and must be replaced. Keep the real external process adapter; a thin delegating observer may capture actual ProviderInvocation fields but must return real adapter outcomes unchanged.

Before valid answers, wrong runtime ID must reject PENDING_REQUEST_MISMATCH and an invalid exact-contract answer must reject ANSWERS_INVALID. Both cause zero run-file byte changes and zero new readiness/inference. Acquire the existing run lock before validation/mutation; every incompatibility/evidence/reference check precedes the first write.

Freeze answer persistence as answers/<runtime-request-id>.json containing the exact validated answer object, bound by answerRef/answerSha256 on its existing pending entry. Freeze request.answered as the event containing runtime requestId, kind and nodeId, without answer content. The writer persists answer bytes, then event history, then atomic checkpoint last. An orphan answer file is not an applied answer. Partial A answer returns needs_input with only B in result.requests and first-request compatibility alias; no provider is dispatched. Keep prior request and committed answer history.

The final B answer permits continuation only after all questions are committed and evidence is verified. A/B each get a new invoke callId and next attempt; parentCallId is that same node's verified completed question call. Deliver only its own validated answer history in both ProviderInvocation.answers and buildPrompt's clarification section, using independent values. Preserve old question calls and seed bytes/call identity; no accepted or active/uncertain work is replayed. Final accepted outputs follow aliases and every node must complete. Preserve prior ordered events/metrics instead of initializing them empty on restore. inputs.json never changes.

Root will split concrete source ownership after the frozen test exposes the actual boundary; this design does not authorize implementation. Fresh-process/crash/lock/corruption/version/reference controls remain separate P4 packets and must not be declared complete by this happy continuation journey. Source version1 behavior stays intact. Root/Sol review, bounded cleanup, two-correction stop, real files/children and no live inference remain mandatory.
