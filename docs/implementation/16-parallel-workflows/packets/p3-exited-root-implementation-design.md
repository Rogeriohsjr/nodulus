Latch the actual ChildProcess exit event/state without clearing the timer or abort listener at exit: a descendant may still retain captured pipes, so the operation remains incomplete until close. At Windows native kill dispatch, recheck the actual child's exit state. The provider's queued termination microtask must do that check itself. If the root is already observed exited, skip taskkill against its numeric PID, record PROCESS_TREE_UNVERIFIED with the original termination cause, and destroy only owned stdout/stderr streams to allow bounded close/settlement. Preserve the natural root exit code and bytes captured so far, first cancellation/timeout/output-limit flags, and launch evidence. A natural path that receives no termination request gains no uncertainty flags.

Pass the actual ChildProcess to the validator's kill helper for its final dispatch check; do not retain only a bare PID. A close occurring before queued dispatch must not be described as successful tree termination. Keep POSIX process-group behavior and legacy feedback error mapping unchanged. No artifact or success result is fabricated for a cancelled operation.

This avoids the observed-exit path, not every OS race. A root can physically exit between the final state check and taskkill starting; eliminating that separate last-instruction race requires OS-level identity/containment. The safe pinned regression proves the observable window without forcing PID reuse. No connection to the unexplained worker/fixture exits is established.
