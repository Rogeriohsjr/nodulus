## Frozen contracts after Sol design findings

The runner's unresolved outcome is {status:'unresolved',nodeId,callId,attempt,launch,operation:'readiness'|'invoke'|'repair_response',cause:{code:'GRAPH_CANCELLED'|'PROVIDER_TIMEOUT',message}}. It has no completed-call or settled failure. A settled error may additionally carry cleanupUnverified {code:'PROCESS_TREE_UNVERIFIED',message,operation}. Graph-stop unresolved peers retain the initiating sibling's terminal error; an unresolved operation whose first stop was its own profile deadline uses PROVIDER_TIMEOUT. A required publication failure overrides the public code with RUN_STORAGE_FAILED and retains the initiating error under cause; it cannot fabricate a successful checkpoint.

Sealing is a runtime-owned publication fence. The internal invocation may carry RuntimeEvidencePublication with run<T>(write:()=>Promise<T>):Promise<T> and isSealed():boolean; its core owner alone can sealAndDrain. Track only concrete runtime filesystem mutations, never the provider/process wait or arbitrary custom-provider IO. Seal prevents new mutations and drains ones already started before first public return; required recovery/final writer commits also finish first. This bounds an unresponsive external operation by the fixed grace plus real durability/fence work; it does not promise to forcibly bound stalled OS storage. Every post-await runner/capture/default-save path and queued writer transition checks the call generation. Do not treat a pre-write boolean alone as a fence.

Each B2/C transition publishes node event(s), node state and graph recovery summary with one writer commit, checkpoint last. The same detailed selected error, including identity, cause and recovery lists, must be saved in result.json/checkpoint and returned publicly. Close local admission synchronously on stop intent, before awaiting persistence. Recheck admission/cancellation after awaited admit/callStarted and before launch; a later delivered earlier-native failure can replace a provisional reason but never reopen admission.

Refined ownership: main Luna owns graph-node-runner.ts, execute-graph-workflow.ts, graph-state.ts, core/ports/provider.ts and one new pure core graph-operation.ts helper for the bounded operation/publication lifecycle. Separate Luna owns only process-runner.ts (C1 change already frozen), default-provider-port.ts and captured-process.ts to use the publication fence around actual builtin evidence writes. The neutral physical-process.ts contract stays frozen. No validator/storage/v1 executor/test changes. The combined observed B2/C1 REDs authorize this integration once the final contract is reviewed; later C stage extensions/P16 remain separate.
