# P15 design checkpoint: graph-owned stop and bounded operations

This is a future design-review packet, not implementation dispatch. Root and Sol read the existing public/port surfaces and graph modules. Current graph calls do not yet pass abort signals or bound custom port promises. Do not describe the fixed-grace contract as implemented.

## Surfaces and intent

Public `runWorkflow(request, provider)` has no caller AbortSignal. Exercise stop through an actual terminal branch error; do not invent a public caller-cancel option. Existing provider invocation, readiness options and artifact-validator ports already accept an optional signal. Use a graph-owned stop intent to distinguish sibling cancellation from a profile/validator timeout and the version-1 feedback deadline. Preserve the version-1 adapter's FEEDBACK_LIMIT_EXCEEDED behavior.

Provider readiness/invoke/response-only repair operations are bounded by their profile timeout plus cleanup grace, including custom ports. Align the graph timeout clamp with the existing adapter policy: finite timeoutMs clamped to 1..600000 ms, otherwise 600000 ms. A shared pure helper is permissible; core must never import a concrete adapter. The graph drain grace is fixed at 5000 ms, not a speed assertion. Executable validators retain their declared timeout and receive graph-stop signals.

The first observed terminal error closes admission and signals active siblings. Pause alone closes admission and drains without aborting siblings. A later real error while draining a pause becomes terminal and initiates stop. Preserve accepted siblings and the initiating diagnostic; induced cancellation is not a new primary failure. Required storage failure remains a publication-poisoning condition and must be visible as RUN_STORAGE_FAILED when it prevents saving an error transition.

## Proposed diagnostic fields to review before tests

- A cooperative canceled sibling ends in node phase `failed`, existing `failure:{code:"GRAPH_CANCELLED",message}`, its current callId and honest launch true/false/null. Record the existing node.failed event with GRAPH_CANCELLED. The top-level error retains the initiating code and identifies its nodeId/callId/launch; induced cancellation never replaces it. A timeout observed first keeps its timeout identity even after a later upstream abort. Cancellation cannot be reported as a feedback limit.
- Cancellation before invoke is definitely unlaunched (`launch:false`); a running default inference has launch true. If launch evidence is unavailable, retain null. Readiness probes are not inference launches.
- An operation unresolved after grace remains phase `active`, with `recoveryRequired:true`, honest launch evidence and a distinct `interruption:{code,message}` diagnostic. The existing failure field belongs only to settled failed nodes. Set `graph.recoveryRequired:true`; result.error also reports recoveryRequired and ordered uncertainNodeIds. Do not claim failed/settled or emit provider.call.completed for a still-pending operation. A node.recovery_required event records the interruption. No late resolution may publish acceptance, events or successors after API return.
- A logical graph profile timeout is PROVIDER_TIMEOUT; an executable validator timeout is VALIDATOR_TIMEOUT. Physical transport flags retain their actual first cause: a native process timer gives timedOut true/cancelled false, while a graph-owned signal (including a logical profile deadline that fires before the native timer) gives cancelled true/timedOut false. Do not infer timedOut merely from an abort reason. A later timer/abort cannot set contradictory flags or erase an already observed native timeout. Preserve legacy feedback deadline classification.
- Use an exact typed AbortSignal.reason for graph_stop versus profile_timeout. Existing signals without that typed reason retain legacy behavior; a generic Node DOMException reason is not a graph tag. No new provider port method or caller API is needed. Required storage publication failure takes the public RUN_STORAGE_FAILED code while retaining the initiating cause code/node/call and original node evidence.

These fields are proposed until Sol/root close the design review; do not silently add phases or contradictory completion events.

## Small test packets

P15A: two actual-default-provider cases. One failing branch while another inference has a parent and descendant alive; one failing branch while the sibling is still in a real held readiness probe. A thin delegating observer records supplied signals/call identity. Assert the required port signal exists before the error is released: the current missing signal then gives prompt meaningful RED, rather than waiting for a fixture watchdog. GREEN continues through actual abort, captured transport, no new admission, honest launch evidence and both owned PIDs dead before API return. Reuse FB080 process-tree patterns; no internal process/storage replacement. Release/drain every fixture in cleanup.

P15B: real graph profile deadline and validator timeout controls, plus a noncooperative external provider that ignores its signal. State whether the profile fixture reaches the graph timer or native process timer; assert its honest physical flags, not a blanket timeout flag. Retain the existing FB080 native timeout and feedback controls. For the noncooperative case, observe the supplied signal, trigger a sibling error, leave its provider promise unresolved through the fixed grace, require the uncertainty record, then resolve it deliberately and prove checkpoint/events/accepted outputs/admission remain unchanged. Attach a rejection sink and drain it during cleanup; do not claim the provider was killed. The runner must gate every continuation after an awaited provider/validator result, including raw/evidence writes, rather than only writer.accept.

Only after accepted RED may Luna implement the small operation controller/node/executor integration. Windows process-tree cleanup must be awaited if required for the new guarantee; retain all FB080 legacy assertions. Split implementation further if the packet is too large. Root and Sol independently review stable tests and source; all remaining P2 gates still apply.
