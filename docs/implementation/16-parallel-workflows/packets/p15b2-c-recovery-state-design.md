# P15B2/C design: unresolved operation versus unverified cleanup

Root/Sol reviewed this distinction against current graph state and ports. It is a future contract/design checkpoint, not source dispatch. B1 deadlines and platform follow-ups are still being written; no unresolved-operation/cleanup feature is claimed implemented here.

B2: a provider operation still pending after the fixed5000ms cleanup grace remains node phase active, with its actual callId/attempt/launch, recoveryRequired=true and interruption {code:'GRAPH_OPERATION_UNRESOLVED',message}. Preserve the logical abort/timeout reason as cause metadata without a failure field that falsely declares settlement. Emit node.recovery_required once; no provider.call.completed for the pending operation. A generation/seal guard must prevent post-await raw/result/validation/metrics/event/acceptance publication when that promise later resolves or rejects. A bare race returning early is insufficient; keep a rejection sink and test deliberate late completion.

C: a settled provider-root operation can be node phase failed with its real GRAPH_CANCELLED/PROVIDER_TIMEOUT/VALIDATOR_TIMEOUT failure and a separate cleanupUnverified {code:'PROCESS_TREE_UNVERIFIED',message,operation:'readiness'|'invoke'|'repair_response'|'validator'}. Emit node.cleanup_unverified (or an atomically equivalent failure payload). Keep truthful completed-call/transport evidence when that logical call actually settled. Existing graph callStarted happens before readiness: a readiness-only logical call may complete as unlaunched/launch=false; it must never acquire a fabricated inference transport. Validator cleanup uncertainty must not erase an already completed provider call. Actual unsettled readiness still follows B2, not C.

Both set graph.recoveryRequired=true and expose declaration-ordered, deduplicated uncertainNodeIds (B2 only) versus cleanupUnverifiedNodeIds (C only), mirrored into result.error with recoveryRequired=true while preserving the initiating code/node/call/launch. Empty lists may be omitted consistently. Single-writer publication must persist the node record, event and graph summary together with the existing authoritative checkpoint protocol. Strict later recovery validates IDs/phases/evidence and rejects both states until explicit recovery; orphan artifacts cannot authorize replay. Schema2 resume is currently rejected, so no existing successful recovery path is changed by this design.

Propagate neutral physical cleanup status/error through actual process/validator adapters and default readiness/invoke/repair catches. Core must not import concrete adapters or gain a caller API. Preserve actual root started/cancelled/timedOut/exit evidence. Successful Windows taskkill and root close cannot certify an earlier orphaned descendant; without owned containment, conservatively report cleanup uncertainty. A real control keeps root alive while an intermediate spawns a descendant and exits, then fails a separate graph branch; require honest root evidence plus uncertainty before finally releasing the known owned descendant. This avoids pretending unknown work is settled. Windows Job Object containment is outside this slice's selected implementation; no late-assignment claim is made.

No frozen P15A known-PID/first-return assertions or legacy deadline diagnostics are weakened. B2's active state and C's failed-but-cleanup-unverified state must not be conflated. Root freezes final exact test assertions before the next implementation packet, with real fixtures and independent evidence.
