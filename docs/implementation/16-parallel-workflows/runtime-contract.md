# Frozen graph runtime decisions

These are coordinator decisions for the implementation packets. They refine the plan; tests and runtime acceptance remain pending. Existing version-1 workflows and bounded feedback routing retain their implementation. A version-2 graph combined with feedback routing is rejected.

## Definition and resource ownership

A graph has `schemaVersion:2`, an ID, declared `nodes`, optional existing caller `inputs`, required `execution:{kind:"dag",maxConcurrency,dependsOn}`, and nonempty ordered `outputs:[{name,from,contract}]`. Every node has its own dependency entry; roots use an empty array. Mapping sources must be declared transitive ancestors. Node declaration order breaks ties among ready nodes; it does not constrain topology. All declared nodes must complete before workflow success, even when an earlier subset join already completed.

P1's `workflow.executionSupported:false` and valid-schema-2 execution rejection are staging contracts. When P2 deliberately introduces the executor, its test-first packet must update the capability to true and replace the staging rejection control with an invalid-graph no-probe/no-write control, while retaining P01's graph fields, ordering, side-effect-free inspection and version-1 regression assertions. Record the intentional test/hash transition; do not retain an inaccurate unsupported capability or remove preflight side-effect coverage. The complete feature is not merge-ready until recovery and delivery gates pass.

`execution.resources` is an optional map from declared node ID to an array of unique safe symbolic resource keys. Unknown node IDs, duplicate keys, unsafe names and non-array entries are rejected. An omitted node entry defaults to the exclusive key `workspace`. An explicitly empty array declares the node independent of shared resources. Equal keys serialize nodes; disjoint keys allow concurrency. This author declaration is not sandbox enforcement or proof that arbitrary tools avoid side effects. It includes the node's validators and response repairs. Runtime-owned call, attempt and run state is always isolated/serialized regardless of declared resources.

Reservations apply within one graph run; coordination of separate runs is outside this slice. Reserve a node's entire key set atomically before admission, never one key while waiting for another. Scan ready nodes in declaration order while skipping resource-blocked nodes so an unrelated ready path can progress. A node cannot consume a concurrency slot while waiting to obtain its declared resources.

A concurrency slot and its resources are held from node admission through readiness probes, inference, response-only corrections, executable validators and durable acceptance publication. Provider response arrival does not release them. A paused or failed node releases its slot only after its processes settle. No new nodes are admitted once a pause or error closes admission.

## Runtime and persistence ownership

Use a separate core graph executor and node runner, with only safely shared pure protocol/mapping helpers. The version-1 feedback-aware executor remains intact. Application composition dispatches by captured workflow version; core never imports concrete storage/provider adapters or CLI formatting.

One graph state writer owns checkpoint, event sequence, metrics, pending answers and final result transitions. Node branches may write only their disjoint attempt and call evidence. A commit writes immutable node result/validation/artifact/provenance or pending-request evidence first, appends its event in the writer queue, then atomically replaces `run.json` last. That checkpoint replacement publishes acceptance; successors cannot start before it. Atomic per-file storage replacement is not a multi-file transaction.

Graph checkpoints use schema version 2 and captured engine/definition versions. They track each node's phase (`not_started`, `active`, `accepted`, `pending`, or `failed`), attempt/call identity and launch evidence, accepted references and hashes, pending request IDs and committed answer references, admission closure, and event-sequence projection. The checkpoint is resume authority. Event history corroborates it and must be reconciled/diagnosed; orphan events or artifacts cannot authorize a call replay. Interruptions before/after the commit point are explicit fixture scenarios.

The initial checkpoint shape is `{schemaVersion:2,engineVersion:"1.0.0",runId,workflow,phase:"execution",status,completedNodes,graph:{nodes,pendingRequests,admissionClosed,nextEventSequence,captured,callerInputs}}`. `graph.nodes` has exactly the declared node IDs, each initially `{phase:"not_started",attempt:0}`. Admission records the attempt and runtime-owned `callId` before invocation; launch evidence is true/false/null. An accepted node has `accepted:{attempt,callId,resultRef,resultSha256,validationRef,validationSha256,responseRef,responseSha256,artifacts:[{name,contract,ref,sha256}]}`. Paths are canonical run-relative paths derived from node/output/attempt identity, and hashes bind the exact saved UTF-8 bytes. `completedNodes` follows declaration order and contains only accepted nodes.

`graph.captured` binds `definitionsSha256`, `inputsSha256`, `referencesSha256`, and optional `pricingSha256` to the intake files. Captured graph definitions include hashes of executable validator entry files; verify them before node probes and again before validator execution, and reject changed policies. Imported validator dependencies still require explicit workspace references; these hashes are consistency checks, not signed proof. Pending entries are keyed by runtime request UUID and contain `{nodeId,kind,attempt,requestRef,answerRef?}`; workflow caller-input requests have null node identity and kind `caller_inputs`. Answer/value state must agree with the captured inputs and committed answer files.

The writer creates the next state privately and publishes its in-memory projection only after the checkpoint write succeeds. A failed required commit closes admission and poisons later queued state transitions; it cannot be followed by a successor launch or a success checkpoint. Optional telemetry failure remains diagnostic with unknown measurements and must not repeat inference or reject an otherwise valid artifact. An unresolved active operation on interruption remains recovery-required rather than being inferred complete from a stray file.

Every invocation/repair gets its own call identity. DAG execution reads call-keyed telemetry only; a legacy custom provider with only `usageForLastCall` has unknown DAG usage rather than a possibly misattributed value. Keep version-1 fallback compatibility. Cancellation intent belongs to the graph executor: distinguish graph stop from provider/validator timeout and feedback-region deadline. A graph cancellation must not be reported as a feedback limit merely because the current adapter uses that code for an aborted signal. Preserve true/false/unknown launch evidence and wait for bounded process cleanup before returning a stable stop.

## Pause, terminal state and resume

Precedence is `error > needs_input > success`. A clarification stops admission and drains already active bounded calls, collecting every runtime-owned request ID and accepted sibling result. A draining sibling error makes the run terminal error; pending data is diagnostic only. A terminal error cannot be resumed by answering a pending question.

Required typed caller inputs are validated before any node admission. Missing/invalid caller data creates a workflow-level pending request with an explicit caller-input kind, not a fictional node output. A valid answer updates committed caller inputs and then permits scheduling. Version, saved-artifact and workspace-reference compatibility checks run before answer mutation or provider probes. Resume uses captured instructions/profiles/contracts rather than silently adopting current definitions.

Answer one pending ID per locked operation. Validate the ID and answer fully before writes; write the answer and its event, then checkpoint the applied answer. With any unanswered saved questions, remain paused and dispatch nothing. Once all are committed, resume eligible pending nodes, never accepted siblings. A missing checkpoint commit after an answer write is diagnosed rather than inferred from an orphan answer file.

The existing top-level `success`/`needs_input`/`error` API envelope is retained. A graph pause returns `result.requests`, ordered by workflow node declaration and containing the unanswered runtime-owned request objects with node identity. `result.request` is the first unanswered request for compatibility with single-question callers. Each request includes its runtime ID, questions and answer contract; answering one request can return the next while no provider is launched. Completed graph results expose the declared output aliases using the existing `{name,contract,data}` artifact shape. No result is selected by whichever branch finished last.

Fresh-process resume verifies captured definitions, versions, referenced artifact/result/validation identity and hashes, input references, event consistency and run-lock ownership. A graph left running with active or possibly launched calls requires explicit recovery; it is not silently replayed. Failed/corrupt/incompatible state fails closed. Named final output aliases are materialized from accepted artifacts in declared order, independent of completion order.
